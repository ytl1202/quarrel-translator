# 网页 Demo

一个纯静态演示页，零依赖、无构建步骤。页面分两个可切换的板块，共用一个模型配置。

## 两个板块

| 板块 | 输入 | 输出 |
| --- | --- | --- |
| 截图分析 | 微信 / QQ 聊天截图 | 逐句翻成「情绪 / 事实 / 需求」+ 固定三段收尾 |
| 对话回复 | 对方刚说的话（可加「我想表达什么」） | 3 条可直接复制的回复：克制版 / 直说需求版 / 先缓一缓版，每条附一句说明 |

**截图不是在本地 OCR**。按当前设计，图片会以 base64 发给你在页面里配置的、支持图片输入的模型，由模型读图并直接按规则输出。好处是一步到位、不用校对识别结果；代价是图片会离开浏览器，且需要模型支持 vision、端点接受 data URL。

## 本地打开

直接双击 `docs/index.html`（`file://` 也能用）：

- 两个板块都有**内置示例**，点「看示例输出」即可看到渲染效果，不需要 API、不联网。
- 真实分析需要配好模型。在 `file://` 下浏览器跨域限制更常见，需要时在本仓库根目录跑 `python -m http.server 8000`，访问 `http://localhost:8000/docs/`。

## 截图板块怎么用

1. 展开顶部「模型接入设置」，填 Base URL / API Key / 模型名，模型需支持图片输入。
2. 把截图**拖进虚线框**、点「选择图片」，或直接 **Ctrl+V 粘贴**。最多 4 张。
3. 页面把每张图长边压到 1600px、转成 JPEG data URL 再发送（不写入磁盘、不上传到别处）。
4. 可选填「补充给模型的话」，例如「右边是我」。
5. 选「翻译范围」。截图往往超过 6 条消息，先把范围告诉模型，就不用再追问一次。
6. 点「分析截图」。

发送给模型的 user content 是 OpenAI 兼容的多模态数组：一个 `text` 段（范围 + 补充说明），后面跟若干 `image_url` 段，值为 `data:image/jpeg;base64,...`。如果端点只接受图片 URL、不接受 data URL，会请求失败并在页面上给出提示。

图片里的头像、昵称、手机号等请先自行遮掉。聊天记录属于私人信息，公开发布这个页面不代表页面会替你保管或脱敏。

## 回复板块怎么用

1. 把对方刚说的话贴进输入框，可选填「我想表达什么」（这一栏只作为你自己的意思，不会被当成对方说过的话）。
2. 点「生成推荐回复」。
3. 输出 3 条，每条可单独复制。页面会在本地检查每条回复里有没有「你总是」「你从来」「你能不能别」和感叹号，命中就在该条下面标出，不把它当成合格回复。

回复板块用普通文本模型即可，不需要 vision。

## 规则相关的兜底

- 两个板块都先做本地停机预检（词表兜底），命中【必须停下的情况】类型时直接展示固定停机句，不发请求。**图片里的内容无法本地预检**，截图板块只检查了补充说明文字；词表会漏也会误判，未命中不代表安全，最终以规则原文和模型输出为准。
- 停机输出走独立面板，不套用翻译格式，也不给回复建议。
- 翻译输出识别不了标准格式时自动退回「原始文本」视图；回复输出识别不到 3 条时也一样。
- 输出区可展开「查看 / 复制当前板块的提示词」，按板块切换内容。截图板块复制的是 `SYSTEM_PROMPT.md` + `SCREENSHOT_PROMPT.md`，回复板块复制的是 `REPLY_PROMPT.md`。图片无法复制到剪贴板，页面上会提示连同截图一起粘到模型对话框。

## 发布到 GitHub Pages

仓库 Settings → Pages → Source 选 **Deploy from a branch** → Branch 选 `main`、目录选 `/docs` → Save。发布后访问 `https://<用户名>.github.io/<仓库名>/`。`docs/.nojekyll` 已放好。

页面所有依赖都在 `docs/` 内，不引用仓库根目录文件，所以 `/docs` 发布模式下不会有坏链。

## 提示词从哪里来

启动时会依次尝试读取 `../` 和 `./` 下的 `SYSTEM_PROMPT.md`、`SCREENSHOT_PROMPT.md`、`REPLY_PROMPT.md`，提取 `text` 代码块覆盖内嵌副本；读不到就用 `data.js` 里的副本。页脚显示实际来源。

在 `/docs` 发布模式下根目录的 md 不会被发布，通常显示「内置副本」。想让 Pages 自动读最新版，把三份 md 复制一份到 `docs/` 下即可。

**改规则原文时，根目录 md 和 `data.js` 里对应的 `FALLBACK_*` 要一起改**；改 `examples/` 的输出时，`SHOT_DEMOS` / `REPLY_DEMOS` 也要一起改。

## 关于 API Key

- Key 只存在当前页面内存，不写入 localStorage、cookie 或日志，刷新即失效。
- 页面只向你所填的 Base URL 发请求。
- 官方明确 GitHub Pages 站点不应用于敏感事务。公共或共用电脑上不建议填真实 Key；这是演示页，不是生产应用。

## 文件

| 文件 | 作用 |
| --- | --- |
| `index.html` | 两个板块的页面结构 |
| `style.css` | 浅色主题样式，无外部字体与 CDN |
| `data.js` | 三份提示词副本、两组内置示例、停机预检词表 |
| `app.js` | 图片压缩与粘贴、多模态请求、输出解析渲染、禁止句式校验、复制 |
| `.nojekyll` | 让 GitHub Pages 跳过 Jekyll |
